<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author → CI runner | PR code and metadata run in CI with the repository token |
| CI → GitHub API | the gate posts a PR comment with GITHUB_TOKEN |
| CI → PyPI | coverage tools installed at run time |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-08 | Elevation of Privilege | GITHUB_TOKEN scopes in build.yaml | high | mitigate | Workflow permissions contents read; only coverage-gate gets pull-requests write and issues write; asserted by the Task 2 verify |
| T-01-09 | Tampering | run scripts receiving PR metadata | high | mitigate | Context values passed only through env:, quoted in ci_coverage_gate.sh; no PR head-ref/title/body expressions; acceptance greps enforce it |
| T-01-10 | Elevation of Privilege | fork pull requests | medium | mitigate | Plain pull_request trigger only (fork PRs get a read-only token); comment step runs only when SAME_REPO is true; comment failure is a warning |
| T-01-11 | Information Disclosure | coverage upload | medium | mitigate | No third-party service or action (D-06); first-party actions only, enforced by an acceptance grep |
| T-01-12 | Tampering | baseline auto-update | medium | mitigate | CI never commits or pushes; baseline changes only via reviewed PR commits (D-12); acceptance grep |
| T-01-SC | Tampering | pip installs in CI | high | mitigate | Install only from tests/unit/requirements-coverage.lock.txt (exact pins approved in plan 01-03) with --only-binary=:all: into a job-local virtualenv |
</threat_model>
